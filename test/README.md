# Desktop Robot - 测试套件

## 概述

本项目包含三套测试套件，用于验证桌面自动化机器人的各项功能是否正常。

## 测试文件结构

```
test/
├── README.md          # 测试文档（本文件）
├── unit.test.js       # 单元测试套件
└── mock.test.js       # 模拟测试套件
test.js                # 功能测试套件（根目录）
```

## 运行测试

### 运行所有测试
```bash
npm run test:all
```

### 仅运行功能测试
```bash
npm test
# 或
node test.js
```

### 仅运行单元测试
```bash
npm run test:unit
# 或
node test/unit.test.js
```

### 仅运行模拟测试
```bash
npm run test:mock
# 或
node test/mock.test.js
```

## 测试断言说明

测试套件使用以下断言函数：

- `assertTrue(condition, message)` - 验证条件为真
- `assertEqual(actual, expected, message)` - 验证值相等
- `assertArrayEqual(actual, expected, message)` - 验证数组相等

## 模拟工具类

模拟测试提供了以下模拟工具类：

### MockIPC
模拟 IPC 调用，支持：
- 注册 IPC 处理器
- 调用日志记录
- 异步调用处理

### MockRobot
模拟 RobotJS 操作，支持：
- 鼠标移动和点击
- 键盘输入和快捷键
- 屏幕信息获取

### MockLocalStorage
模拟 localStorage，支持：
- 数据存储和读取
- 数据清除

## 添加新测试

### 添加功能测试

在 `test.js` 中添加：

```javascript
await test('测试描述', () => {
  // 测试逻辑
  assertTrue(condition, '错误信息');
  assertEqual(actual, expected, '错误信息');
});
```

### 添加单元测试

在 `test/unit.test.js` 中添加：

```javascript
describe('测试组名称', () => {
  it('测试用例描述', () => {
    // 测试逻辑
    assertTrue(condition, '错误信息');
  });
});
```

### 添加模拟测试

在 `test/mock.test.js` 中添加：

```javascript
describe('测试组名称', () => {
  it('测试用例描述', async () => {
    const ipc = new MockIPC();
    const robot = new MockRobot();
    // 测试逻辑
    assertEqual(actual, expected, '错误信息');
  });
});
```

## 测试最佳实践

1. **独立性**：每个测试应独立运行，不依赖其他测试的状态
2. **可重复性**：测试应始终产生相同的结果
3. **快速执行**：测试应快速执行，避免过长的等待
4. **清晰命名**：测试名称应清晰描述测试目的
5. **单一职责**：每个测试只验证一个功能点

## 故障排除

### 测试失败常见原因

1. **文件路径错误**：确保从项目根目录运行测试
2. **缺少依赖**：运行 `npm install` 安装依赖
3. **文件不存在**：检查源代码文件是否存在

### 调试测试

在测试中添加日志输出：

```javascript
await test('调试测试', () => {
  console.log('调试信息:', variable);
  assertTrue(condition, '错误信息');
});
```
